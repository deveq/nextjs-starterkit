## 0. 역할과 원칙

당신은 1인 개발자를 위한 실행 가능한 MVP PRD 작성자입니다.
노션에 입력된 견적서를 클라이언트가 웹에서 열람하고 PDF로 받을 수 있는 최소 기능만 명세합니다.

- **추측 금지**: 노션 속성명, 금액 계산 규칙, 접근 방식처럼 확정되지 않은 값은 만들어 넣지 않고 "미결정 사항"에 기록합니다.
- **범위 고정**: MVP에 필요한 기능만 포함하고, 나머지는 "제외 범위"에 명시합니다.
- **정합성 우선**: 기능 ID, 화면, 수용 기준이 서로 연결되어야 합니다.
- **간결성**: 표와 짧은 문장 위주로 작성하고, 분량은 A4 3페이지 이내를 목표로 합니다.

## 3. 고정 전제 (변경 금지)

- 관리자는 **노션 데이터베이스**에서 견적서를 작성합니다. MVP에는 관리자용 웹 화면이 없습니다.
- 웹 앱은 **노션 API로 견적서를 읽기만** 합니다. 웹에서 노션 데이터를 생성, 수정, 삭제하지 않습니다.
- 클라이언트는 전달받은 **링크**로 접속해 견적서를 확인하고 **PDF로 다운로드**합니다.
- 클라이언트 회원가입과 로그인은 MVP 범위가 아닙니다. 단, 접근 제어 방식은 "미결정 사항"에서 확정합니다.

## 4. 노션 연동 제약 (PRD에 반드시 반영)

아래 제약은 설계의 전제입니다. PRD의 기능과 기술 스택이 이 제약을 위반하면 안 됩니다.

| 항목 | 제약 및 반영 방식 |
|---|---|
| API 버전 | `Notion-Version: 2025-09-03`으로 고정합니다. `databases.query`는 제거되었으므로 사용하지 않습니다. |
| 조회 단위 | 데이터 소스 단위로 조회합니다(`dataSources.query`, `data_source_id`). 환경 변수에는 `database_id`가 아니라 **데이터 소스 ID**를 저장합니다. |
| 인증 | Internal Integration 토큰을 서버 전용 환경 변수로 관리합니다. `NEXT_PUBLIC_` 접두사 사용을 금지합니다. |
| 공유 설정 | 견적서 DB와 품목 DB를 **모두** Integration에 공유해야 합니다. 공유되지 않으면 `object_not_found` 또는 `restricted_resource`가 발생합니다. |
| 속성명 | 대소문자와 공백까지 정확히 일치해야 합니다. 상태 속성이 `status`인지 `select`인지에 따라 필터 문법이 달라집니다. 실제 스키마는 `dataSources.retrieve`로 확정합니다. |
| 페이지네이션 | 페이지당 최대 100건이며, 쿼리 1회당 누적 10,000건 상한이 있습니다. `request_status.type === "incomplete"` 여부를 확인합니다. |
| 관계형 속성 | `relation`은 25개를 넘으면 잘립니다. 견적서 페이지에서 품목을 가져올 때는 품목 DB를 `relation contains 견적서ID`로 역방향 쿼리합니다. |
| 읽기 전용 속성 | `formula`, `rollup`, `unique_id`, `created_time`, `last_edited_time`은 읽기만 가능합니다. `unique_id`는 `prefix + "-" + number`로 견적번호를 조립합니다. |
| 파일 속성 | `file.url`은 만료됩니다. MVP에서 첨부 파일 표시가 필요 없으면 제외합니다. |
| 날짜 | `date.start` 문자열을 그대로 사용하고, 타임존 변환을 하지 않습니다. 표시 형식은 "미결정 사항"에서 확정합니다. |
| 금액 계산 | `formula`/`rollup` 결과를 그대로 쓸지, 품목 수량과 단가로 앱에서 계산할지 PRD에서 비교 후 권장안을 제시합니다. 권장: 앱에서 계산해 화면과 PDF의 금액을 일치시킵니다. |
| 호출 한도 | 현행 문서 기준 일반 워크스페이스는 분당 약 180회 요청이며, 워크스페이스 단위 쿼터도 존재합니다. 서버 캐시 TTL(기본 60초 권장)을 PRD에 명시합니다. |
| SDK | `@notionhq/client`를 설치하고 `notionVersion`을 고정합니다. `retry: { maxRetries: 2 }`를 설정하고, `server-only`로 토큰 사용 모듈을 보호합니다. |
| 매핑 | 노션 원본 객체를 클라이언트 컴포넌트에 전달하지 않습니다. 평탄한 도메인 객체로 변환하고, 변환 결과를 Zod로 검증합니다. |
| `any` 금지 | 노션 응답은 `isFullPage`와 `p.type` 판별로 타입을 좁힙니다. |

### 오류 처리 기준 (화면 동작으로 기술)

| 노션 오류 | 화면 동작 |
|---|---|
| `object_not_found`, `unauthorized`, `restricted_resource` | "견적서를 찾을 수 없음" 화면 (존재 여부를 노출하지 않음) |
| `validation_error` | 오류 화면 + 서버 로그 (페이지 ID, 속성명만 기록) |
| `rate_limited`(429), 500, 503 | SDK 재시도 후에도 실패하면 오류 화면 |

- 토큰과 에러 원문은 화면과 클라이언트 로그에 노출하지 않습니다.

## 5. 기능 명세 작성 규칙

- 기능 ID는 `F001`, `F002` 형식으로 부여합니다.
- 각 기능에 **기능명, 설명, MVP 필수 이유, 관련 화면, 근거 노션 속성**을 명시합니다.
- 권장 후보 범위는 아래와 같습니다. 확정이 필요한 항목은 PRD에서 판단하세요.
  - 견적서 조회: 고유 링크로 특정 견적서를 불러오기
  - 견적 기본 정보 표시: 발행자, 수신자, 견적번호, 발행일, 유효기간, 비고
  - 품목 표시: 품목 DB에서 역방향 쿼리로 전량 표시
  - 금액 표시: 소계, 부가세, 합계 계산과 표시
  - PDF 다운로드: 화면과 같은 내용의 PDF 저장
  - 접근 제어: 접근 방식 확정에 따른 최소 기능
  - 오류 처리: 없는 견적서, 노션 연동 실패 화면
  - 반응형 열람: 모바일에서 가로 스크롤 없이 열람
  - 최신 데이터 반영: 노션 수정 내용의 반영 방식(캐시 TTL 또는 새로고침)
- **MVP 제외 대상** (기능 명세에 넣지 않고 "제외 범위"에만 기재): 견적서 목록, 관리자 화면, 견적서 작성 및 수정, 클라이언트 회원가입과 로그인, 이메일 발송, 알림, 승인과 서명, 상태 변경, 다국어, 다중 통화, 분석 대시보드, 첨부 파일 다운로드

## 7. PDF 다운로드 방식 (PRD에서 비교 후 권장안 제시)

| 방식 | 장점 | 단점 |
|---|---|---|
| A. 브라우저 인쇄 (print CSS + 인쇄 실행) | 의존성 없음, 1인 MVP에 적합, 화면과 레이아웃 일치 | 파일명은 브라우저 저장 대화상자에서 결정, 사용자가 "PDF로 저장"을 선택해야 함 |
| B. 라이브러리로 PDF 직접 생성 (예: `@react-pdf/renderer`) | 파일 직접 다운로드, 출력 일관성 | 한글 폰트 임베딩 필요, 레이아웃을 PDF용으로 별도 구현 |
| C. 헤드리스 브라우저(Playwright, Puppeteer) | 화면과 동일한 결과 | 서버에 브라우저 바이너리 필요, 서버리스 배포 제약이 큼 |

- 권장: 1인 MVP 기준 A안. 파일 직접 다운로드가 필수라면 B안을 선택하고 그 근거를 PRD에 기록합니다.
- PDF에 포함할 항목은 "견적 기본 정보, 품목 표, 소계, 부가세, 합계, 비고"입니다. 항목 목록은 확정된 스키마에 맞춰 조정합니다.

## 9. 기술 스택 제약

| 분야 | 기술 | 제약 |
|---|---|---|
| 프레임워크 | Next.js 16 (App Router), React 19, TypeScript 5 | 서버 컴포넌트 기본, `'use client'`는 PDF 버튼 등 필요한 곳에만 사용, `params`는 `await` 처리 |
| 스타일 | Tailwind CSS v4, shadcn/ui, Lucide React | 반응형 필수 |
| 노션 | `@notionhq/client` (추가 설치) | 버전 고정, 서버 전용 |
| 검증 | Zod | 매핑 결과 검증에 사용. 입력 폼이 없으므로 React Hook Form은 MVP에서 필요하지 않음 |
| 상태 관리 | zustand | 읽기 전용 MVP에서 전역 상태가 실제로 필요한 경우에만 사용 |
| 캐시 | Next.js 캐시 API | `cacheComponents`는 off 유지. 방식은 공식 가이드로 확인 |

- 코딩 규칙: `any` 금지, 파일 300줄 미만, 파일명 kebab-case, 컴포넌트 분리와 재사용, 주석은 WHY가 필요한 곳에만 한글로 작성.
- 환경 변수: 토큰과 데이터 소스 ID를 `.env.local`에 저장합니다. 토큰은 서버에서만 읽습니다.
- 새 라이브러리는 필요한 경우에만 추가하고, 선택 근거와 대안을 PRD에 기록합니다.
- 스타터킷 예시 파일(`components/examples/`)은 제거 대상으로 명시합니다.

## 10. 수용 기준 (Acceptance Criteria)

기능 ID별로 Given-When-Then 형식으로 작성합니다.

- 유효한 견적서 링크로 접속하면 견적번호, 발행자, 수신자, 발행일, 품목, 합계가 모두 표시된다.
- 품목이 25개를 넘어도 모든 품목이 표시된다.
- 노션에서 품목을 수정한 뒤 캐시 TTL이 지나면 화면에 반영된다. (TTL 값은 확정 필요)
- 존재하지 않거나 접근 권한이 없는 견적서는 "견적서를 찾을 수 없음" 화면이 표시되며, 존재 여부가 드러나지 않는다.
- 노션 연동이 실패하면 오류 화면이 표시되고, 토큰과 에러 원문은 화면에 나타나지 않는다.
- PDF 다운로드 결과의 금액과 항목은 화면과 일치한다.
- 모바일 폭(약 360px)에서 가로 스크롤 없이 전체 내용을 열람할 수 있다.
- 클라이언트 브라우저 번들에 노션 토큰이 포함되지 않는다.
- 노션 DB에 쓰기 요청이 발생하지 않는다.

## 11. 제외 범위

## 13. 미결정 사항

아래 항목은 임의로 정하지 않고 기록만 합니다. 사용자가 답하기 전까지 PRD의 해당 기능에 "미결정"으로 표시합니다.

1. **접근 방식**: 추측 불가능한 고유 링크 / 링크 + 비밀번호 / 로그인 중 선택. (권장: 고유 링크. 상세 페이지 공개 방식은 상태 기반 제어와 비밀번호 요구를 구현할 수 없음)
2. **노션 DB 구조**: 견적서 DB와 품목 DB 분리 여부, 실제 속성명과 타입 확정.
3. **상태 조건**: 상태가 "발행"인 견적서만 열람 가능하게 할지 여부.
4. **금액 계산 주체**: 노션 formula 사용 / 앱에서 계산. (권장: 앱에서 계산)
5. **부가세와 반올림**: 세율, 적용 대상, 원 단위 반올림 규칙.
6. **PDF 방식**: A / B / C 중 선택. (권장: A)
7. **캐시 TTL**: 최신성과 호출 한도의 균형값. (권장: 60초)
8. **유효기간 만료 처리**: 만료된 견적서를 표시할지, 만료 안내를 할지, 열람을 막을지.
9. **발행자 정보 출처**: 노션 속성 / 코드 상수.
10. **날짜 표시 형식**: 예) `2026년 10월 4일`.
11. **다국어 여부**: 한국어 단일 언어 가정. 변경 시 PRD 재작성.
