# 견적서 웹 조회·PDF 다운로드 MVP PRD

> 작성일: 2026-10-04 · 상태: 초안 (미확정 사항은 12장에 옵션으로 정리)

## 1. 개요

**목적**: 노션에 작성한 견적서를 클라이언트가 웹에서 확인하고 PDF로 저장할 수 있게 해, 파일 변환과 재첨부 없이 최신 견적서를 전달한다.

**타겟 사용자**
- **관리자**: 외주 견적을 발행하는 프리랜서 개발자 1인. 노션으로만 작업하고 웹 관리자 화면은 쓰지 않는다.
- **클라이언트 담당자**: 발주처 실무 담당자. 링크로 견적서를 보고 사내 결재용 PDF를 받는다. 회원가입과 앱 설치는 하지 않는다.

### 배경 및 문제
- 엑셀/한글 → PDF 변환 → 이메일 첨부 과정이 수정 때마다 반복된다.
- `견적서_최종_v3.pdf`처럼 버전이 쌓여 클라이언트가 최신본을 찾기 어렵다.
- 모바일에서 첨부 PDF를 확대해 읽기 불편하다.
- 견적 데이터가 노션과 문서 파일에 나뉘어 중복 입력된다.

### MVP 목표
- 관리자는 노션에서 작성과 상태 변경만으로 견적서를 발행한다.
- 클라이언트는 링크로 최신 견적서를 확인하고 PDF로 저장한다.
- 금액(공급가액, 부가세, 합계)은 앱이 계산해 사람이 손으로 계산하지 않는다.

### MVP 범위 요약
- 포함: 견적서 조회 화면, 금액 자동 계산, 발행 상태에 따른 공개 제어, PDF 저장(인쇄), 반응형 레이아웃, 오류 화면, 검색 노출 차단
- 제외: 9장 참고

## 2. 사용자 여정

```
[관리자] 노션 「견적서」 DB에 작성 (제목, 클라이언트, 날짜, 품목 연결 뷰)
   ↓ 상태를 「발행」으로 변경
[관리자] 공유 링크 복사 (노션 수식 속성 또는 앱이 생성, 12장 미확정 8)
   ↓ 링크를 클라이언트에게 전달
[클라이언트] 링크 접속 → 견적서 화면 진입 지점
   ↓ 조건 분기
   ├─ 상태 「작성중」 / 「취소」 / 존재하지 않음 → 404 화면 (종료)
   ├─ 조회 실패 (Notion 장애, 필수 속성 누락) → 오류 화면 (종료)
   ├─ 인증 필요 설정(12장 미확정 3) → 인증 화면 → 통과 시 견적서 화면
   └─ 인증 불필요 설정 → 견적서 화면
   ↓
[견적서 화면] 내용 확인 (데스크톱: 표, 모바일: 카드)
   ↓ 「PDF 다운로드」 클릭
[인쇄 대화상자] 대상 「PDF로 저장」 선택 → 파일 저장 (종료)
```

**자동 리디렉션**: 상태가 공개 상태가 아니면 견적서 화면 대신 404를 바로 응답한다. 인증이 필요한 설정에서 인증이 없거나 만료되면 인증 화면으로 보낸다. 인증 통과 후에는 원래 요청한 견적서 화면으로 돌아간다.

**선택 분기점**: 클라이언트는 「PDF 다운로드」 또는 화면 확인만 선택할 수 있다. 견적 승인, 서명, 결제는 MVP 범위가 아니다.

## 3. 기능 명세 (MVP)

| ID | 기능명 | 설명 | 수용 기준 | 관련 화면 |
|----|--------|------|-----------|-----------|
| F-001 | 견적서 조회 | 견적서 ID로 노션 견적서와 품목을 조회해 화면에 렌더링 | 공개 상태 견적서의 필수 항목(제목, 견적번호, 클라이언트, 발행일, 유효기한, 품목, 합계, 비고)이 모두 표시된다 | 견적서 화면 |
| F-002 | ID 형식 검증 | 노션 페이지 ID 형식이 아니면 조회 없이 404 처리 | 형식이 틀린 ID는 외부 API를 호출하지 않고 404를 반환한다 | 견적서 화면(404) |
| F-003 | 공개 상태 제어 | 노션 「상태」가 공개 상태(예: 발행, 승인)일 때만 내용 공개 | 작성중, 취소, 알 수 없는 값은 404를 반환한다 | 견적서 화면(404) |
| F-004 | 금액 자동 계산 | 품목 금액, 공급가액, 부가세, 합계를 앱에서 계산 | 5장 규칙과 테스트 케이스 10개가 모두 일치한다 | 견적서 화면 |
| F-005 | PDF 저장 | 「PDF 다운로드」 버튼으로 인쇄 대화상자를 열고, 인쇄용 CSS를 적용 | Chrome, Edge, Safari 최신 버전에서 A4 세로로 저장되고, 버튼은 출력되지 않으며, 한글이 깨지지 않는다 | 견적서 화면 |
| F-006 | 반응형 레이아웃 | 데스크톱은 표, 모바일은 카드 목록으로 표시 | 375px 폭에서 가로 스크롤이 없고, 1280px에서 본문 최대 폭은 800px이다 | 견적서 화면 |
| F-007 | 오류 화면 | 404(없음, 비공개, 형식 오류)와 오류(Notion 장애, 데이터 검증 실패) 안내 | 각 상황에서 안내 문구가 표시되고, 내부 오류 메시지나 스택은 노출되지 않는다 | 404 화면, 오류 화면 |
| F-008 | 검색 노출 차단 | 견적서 페이지를 검색엔진에서 제외 | 응답 HTML에 `noindex, nofollow` 메타가 있다 | 견적서 화면 |
| F-009 | 클라이언트 인증 | 인증 방식은 12장 미확정 3에 따라 결정. 인증이 필요하면 인증 화면을 추가 | 인증 방식이 확정되면 수용 기준을 확정한다 (미확정) | 인증 화면 (조건부) |

### MVP 제외 기능
- 관리자 웹 UI (작성, 수정은 노션에서만)
- 로그인, 회원가입
- 견적 승인, 전자서명, 결제
- 이메일, 메신저 자동 발송
- 다국어, 다중 통화(원화만)
- 서버 생성 PDF 파일 다운로드
- 할인 품목(음수 금액), 한글 금액 표기, 유효기한 만료 배너
- 열람 기록, 관리자 대시보드

## 5. 금액 계산 규칙

| 항목 | 규칙 |
|------|------|
| 품목 금액 | 수량 × 단가, 원 미만 절사 (기본안, 12장 미확정 5) |
| 공급가액 | 품목 금액의 합 |
| 부가세 | 부가세 적용 체크 시 공급가액 × 10%, 원 미만 절사. 미적용 시 0원이며 「부가세 미포함」 문구로 표시 |
| 합계 | 공급가액 + 부가세 |
| 수량 | 0보다 큰 수, 소수 둘째 자리까지 |
| 표기 | `1,234,000원` 형식, 0원도 표시 |

- 부동소수 오류를 막기 위해 금액은 정수(원) 단위로 계산한다.
- 단가나 수량이 비어 있거나 음수이면 잘못된 금액을 보여주지 않도록 견적서 전체를 오류 화면으로 처리한다.

## 6. 데이터 모델 (노션 기준 초안)

노션 스키마는 미확정이다(12장 미확정 2). 아래는 필요한 최소 항목 기준 초안이다.

### 견적서 DB
| 필드 | 타입 (초안) | 필수 | 설명 |
|------|-------------|------|------|
| 제목 | title | 필수 | 견적서 제목 |
| 견적번호 | 고유 번호 | 필수 | 예: Q-12 |
| 상태 | status | 필수 | 작성중, 발행, 승인, 취소 (공개 여부 결정) |
| 클라이언트명 | text | 필수 | 수신 회사명 |
| 담당자명 | text | 선택 | 수신 담당자 |
| 발행일 | date | 필수 | 날짜만 사용 |
| 유효기한 | date | 필수 | 견적 유효 마지막 날 |
| 부가세 적용 | checkbox | 필수 | 체크 시 부가세 계산 |
| 비고 | text | 선택 | 결제 조건, 작업 범위 등 |
| 품목 | relation → 품목 DB | 필수 | 0개 이상 |
| 인증 값 | text | 조건부 | 인증 방식에 따라 필요 (12장 미확정 3) |

### 품목 DB
| 필드 | 타입 (초안) | 필수 | 설명 |
|------|-------------|------|------|
| 품목명 | title | 필수 | 예: 메인 페이지 퍼블리싱 |
| 견적서 | relation → 견적서 DB | 필수 | 소속 견적서 |
| 설명 | text | 선택 | 세부 내용 |
| 수량 | number | 필수 | 0보다 큼 |
| 단위 | select | 선택 | 식, 개, 시간, M/M 등 |
| 단가 | number | 필수 | 0 이상 정수(원) |
| 순서 | number | 선택 | 없으면 생성 순 |

**품목 표현 방식**: 품목은 연결 DB(relation)로 둔다. 수량과 단가가 숫자 타입으로 보장되어 금액 계산 오류를 줄인다. 페이지 안 표(table 블록)는 모든 값이 문자열로 들어와 파싱 오류 위험이 있어 비권장한다.

## 7. 기술 구성

### 7.1 스택 (프로젝트 기준)

| 분야 | 기술 | 비고 |
|------|------|------|
| 프레임워크 | Next.js 16 (App Router), React 19, TypeScript 5 | `params`, `searchParams`는 Promise이므로 `await` 필요 |
| 스타일 | Tailwind CSS v4, shadcn/ui | 인쇄용 CSS는 `print:` 변형과 `@media print` 사용 |
| 폼 | React Hook Form + Zod | 인증 폼을 만들 때만 사용 |
| 상태 | Zustand | MVP 조회 화면에는 전역 상태가 거의 없어 필수 아님 |
| 노션 연동 | 노션 공식 SDK 또는 REST 호출 (12장 미확정 1) | 응답 타입은 `any` 없이 타입 정의 |
| 배포 | Vercel (기본 도메인으로 시작) | 환경 변수는 서버 전용과 공개용을 구분 |

### 7.2 노션 연동 방식 (미확정)

| 구분 | A. 노션 페이지 공개 | B. 공식 API 내부 통합 토큰 |
|------|---------------------|---------------------------|
| 인증 정보 | 없음 | 토큰 1개 (서버 환경 변수) |
| 노출 범위 | 공개 링크를 아는 사람 누구나 | 노션 권한 기준, 앱이 공개 상태를 직접 판단 |
| 상태 제어 | 노션 공유 설정에 의존 | 「상태」 속성으로 404 처리 가능 |
| 비밀번호 인증 | 구현 불가 | 가능 |
| 데이터 조회 방식 | 페이지 HTML 또는 비공식 렌더링 (안정성 낮음) | 구조화된 속성 응답 |
| 리스크 | 링크가 전달되면 전부 열람 가능 | 토큰 관리 필요, API 버전 변경 대응 필요 |

**검토 의견**: 금액 데이터의 타입 안정성과 공개 상태 제어가 필요하면 B가 맞다. 공개 범위를 노션 공유 설정으로만 관리하면 충분하다면 A로 단순화할 수 있다. 최종 선택은 사용자 확인이 필요하다.

### 7.3 서버, 클라이언트 컴포넌트 구분

| 구분 | 대상 | 이유 |
|------|------|------|
| 서버 컴포넌트 (기본) | 견적서 페이지, 조회 데이터 렌더링, 404/오류 분기 | 노션 토큰을 서버에서만 사용 |
| 서버 전용 모듈 (`server-only`) | 노션 클라이언트, 데이터 매퍼, 금액 계산 | 토큰이 클라이언트 번들에 들어가지 않도록 차단 |
| 클라이언트 컴포넌트 (`'use client'`) | 「PDF 다운로드」 버튼, 인증 폼(해당 시), 오류 화면의 재시도 버튼 | 브라우저 API(`window.print`), 사용자 입력 |
| 공통 UI (서버 또는 클라이언트 무관) | 견적서 표, 카드 목록, 합계 영역 | 순수 표시 컴포넌트 |

### 7.4 PDF 생성 방식

**기본안: `window.print()` + 인쇄용 CSS**
- 장점: 추가 의존성 없음, 벡터 텍스트라 선택과 검색이 가능, 웹 폰트(Noto Sans KR 등)를 그대로 사용
- 단점: 사용자가 인쇄 창에서 「PDF로 저장」을 직접 선택해야 함, 브라우저마다 여백과 파일명이 다를 수 있음
- 대안: `@react-pdf/renderer`(한글 폰트 파일 등록 필요, PDF용 레이아웃 별도 작성), 서버 생성(함수 크기와 콜드 스타트 부담), html2canvas + jsPDF(이미지라 흐리고 텍스트 선택 불가)

### 7.5 데이터 조회와 캐시

- 노션 API는 평균 초당 3회 제한이 있으므로 매 요청마다 여러 번 호출하지 않도록 설계한다.
- 캐시 방식과 주기는 12장 미확정 6에서 정한다. 기본안은 견적서 ID별 60초 캐시다. 이 경우 노션 수정이 최대 60초 뒤 웹에 반영된다.

## 11. 예외 및 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| 존재하지 않는 견적서 ID, 형식 오류 | 404 화면 |
| 작성중, 취소, 알 수 없는 상태 | 404 화면 |
| 품목 0개 | 「등록된 품목이 없습니다」 표시, 공급가액, 부가세, 합계 0원 |
| 품목 수가 많음 (수십 개) | 전체 조회 후 표시. 인쇄 시 여러 페이지로 나뉘고 헤더 반복 |
| 긴 품목명, 띄어쓰기 없는 URL | 줄바꿈 처리, 금액 열은 줄바꿈 금지 |
| 수량 또는 단가 비어 있음, 음수 | 견적서 전체를 오류 화면 처리 |
| 수량 소수 셋째 자리 이상 | 둘째 자리에서 반올림하고 서버 로그에 경고 |
| 날짜 표시 | 노션 날짜 문자열을 그대로 사용해 시간대 변환으로 하루가 밀리지 않게 한다 |
| 노션 장애, 429 | 캐시가 있으면 이전 데이터 표시, 캐시가 없으면 오류 화면 |
| 노션 필수 속성 이름 변경, 삭제 | 오류 화면, 서버 로그에 속성명 기록 |
| 노션에 새 속성 추가 | 정의된 속성만 읽으므로 화면과 오류에 영향 없음 |
| 노션 이미지(로고 등) | 노션 파일 URL은 시간이 지나면 만료되므로 사용하지 않고 `public/`에 둔다 |
